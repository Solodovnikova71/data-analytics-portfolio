# Private portfolio review checklist

Complete before choosing any public release. An unchecked item is a decision or verification still needed.

## Accuracy and contribution

- [ ] Read all five case studies and confirm each statement reflects your actual work and understanding.
- [ ] Confirm individual contributions and any collaboration or AI assistance; follow the applicable course and platform disclosure requirements.
- [ ] Keep analysis, design, proposals and completed implementation distinct. Do not describe proposed cleansing, migration, integration or deployment as completed.
- [ ] Verify BI filters, totals, revenue versus profit measures, month aggregation and data coverage before publishing any chart.

## Privacy and rights

- [ ] Confirm course rules and permissions before sharing course-derived charts, datasets, scenario material or full reports.
- [ ] Exclude raw datasets, course templates, rubrics, login details, student identifiers, contact details and employer materials.
- [ ] Check every future screenshot, diagram, attachment and document metadata for private or third-party information.
- [ ] Choose any license deliberately. No license file or permission to reuse third-party content has been added.

## Evidence to add if available

- [ ] DAT 300: PBIX file, measure definitions and an approved data source or a clearly labeled synthetic replacement.
- [ ] IT 204: editable model diagrams; SQL scripts and tests only if genuinely created and run.
- [ ] DAT 325 profiling: notebook or script, dependency information and permitted inputs or synthetic test data.
- [ ] For all projects: source credits, assumptions and evidence of any later extension. Do not backdate new work into the original coursework.

## Release decision

- [ ] Select the strongest projects for the target role; three focused examples may be clearer than five equally featured papers.
- [ ] Check every relative link and PDF in the private repository. Confirm repository visibility in GitHub settings.
- [ ] Review the actual files and repository history before a public visibility change; removing a file from the latest version does not remove it from history.
- [ ] Approve public release separately. This review package does not confirm that public redistribution is permitted.
